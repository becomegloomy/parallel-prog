# Parallel-prog

Коллекция из шести небольших C-проектов по параллельному программированию. Одна и та же задача обработки массивов реализована шестью разными способами - от последовательного Intel IPP до GPU через OpenCL. По каждому проекту есть замеры времени, ускорения и графики.

Цель - узнать как разные модели параллелизма влияют на ускорение, где упирается в закон Амдала, где - в передачу данных, и почему «параллельно» не всегда значит «быстрее».

## Проекты

| Проект | Тема | Ключевой вывод |
|---|---|---|
| [`ipp-omp-benchmark`](ipp-omp-benchmark/) | Intel IPP (seq) vs OpenMP | Ускорение растёт до числа ядер, дальше - насыщение из-за последовательной сортировки |
| [`auto-parallelization`](auto-parallelization/) | GCC `-ftree-parallelize-loops` | Auto-parallelization даёт малое ускорение: компилятор не всё распараллеливает |
| [`openmp-stages-benchmark`](openmp-stages-benchmark/) | OpenMP + per-stage тайминги | Ускорение ограничено последовательными `Map M2` и `Sort` |
| [`openmp-tasks-benchmark`](openmp-tasks-benchmark/) | OpenMP tasks + CI95% | Tasks дают **S < 1**: overhead больше выигрыша от параллельной сортировки |
| [`pthreads-benchmark`](pthreads-benchmark/) | pthreads (ручные потоки) | Распараллеливание части этапов не помогает: основное время - в последовательных |
| [`opencl-benchmark`](opencl-benchmark/) | OpenCL (GPU) | GPU ≠ автоматическое ускорение: `upload` + `download` занимают ~75% времени |

## Общая задача

Во всех проектах программа делает **5 независимых экспериментов**. В каждом эксперименте над двумя массивами - `M1` (размер `N`) и `M2` (размер `N/2`) - выполняются этапы:

| Этап | Что происходит |
|---|---|
| **Generate** | Заполнение массивов `M1` и `M2` случайными числами |
| **Map (M1)** | `M1[i] = coth(sqrt(M1[i]))` |
| **Map (M2)** | `M2[j] = sqrt((M2[j] + M2[j-1]) * e)` |
| **Merge** | Поэлементное деление: `M2[j] = M1[j] / M2[j]` |
| **Sort** | Сортировка расчёской (Comb Sort) |
| **Reduce** | Сумма синусов тех элементов `M2`, у которых частное `M2[j] / min_nonzero` - чётное; `min_nonzero` - первый ненулевой элемент после сортировки |

Итоговое значение `X` суммируется по всем 5 экспериментам.

Именно **Map (M2)** и **Sort** - последовательные - ограничивают общее ускорение во всех проектах.

## Общие требования

- **Компилятор:** GCC ≥ 9;
- **CPU-параллелизм:** OpenMP (`libgomp`), pthreads;
- **GPU-параллелизм:** OpenCL ICD loader (`libOpenCL.so`) + драйвер GPU (или fallback на CPU-устройство);
- **Intel IPP:** Intel oneAPI Base Toolkit - только для `ipp-omp-benchmark`;
- **Python 3:** `matplotlib`, `numpy`, `psutil`, `pandas`.
